# g2pkk mecab-less 한계

형태소 분석기 없이는 표면 문자열이 같은 두 발음 현상을 구분할 수 없어,
원본 g2pK가 mecab 어노테이션(STEP 3)으로 처리하던 규칙들이 예외 사전·휴리스틱으로
대체된다. Dart 포트는 `MorphAnalyzer` 주입(2026-10-22)으로 이 한계를 선택적으로 해소한다.

## 형태소 경계가 필요한 규칙

원본 annotate()가 만드는 마커와 그 소비 규칙:

| 마커 | 조건(mecab-ko 태그) | 소비 규칙 | 예 |
|------|---------------------|-----------|-----|
| /P | 용언 어간(V*) + 어말 자모 ㄴ/ㄵ/ㅁ/ㄻ/ㄺ/ㄼ/ㄾ | 제23항 계열 경음화(verbNieun) | 앉다→[안따], 신다→[신따] |
| /E | 어미(E*) + ㄹ | ㄹ 탈락·경음화(modifyingRieul) | 할걸 |
| /B | 단위성 의존명사(NNBC) | 순우리말 수사(numerals) | 3개→[세개] |
| /J | 조사(J*)의 '의' | ㅢ→ㅔ 발음(descriptive) | 나의→[나에] |

마커를 내지 않는 품사는 형태소 경계 정보가 **소실**된다. 부사(M*)의 경우 이
소실이 실결함을 만든다: 붙여 쓴 `못알아먹는다`에서 mecab이 못/MAG+알아먹/VV로
분석해도 어느 규칙에도 경계가 보이지 않아 단어내 연음(link1 `ᆺᄋ→ㅅ`)이 타
[모사라멍는다]가 됐다.

## 부사 ㄷ류 받침 + ㅇ — 어절 경계 삽입 규칙 (제9항·제15항)

표준 발음법 제15항("실질 형태소가 모음으로 시작하면 대표음으로 바꾸어 옮긴다"
— 맛없다[마덥다], 겉옷[거돋])과 국립국어원 온라인가나다('못 올 일이'[모돌 이리])에
따라, annotate()는 **부사(M*)+ㄷ류 종성(ㄷ,ㅅ,ㅆ,ㅈ,ㅊ,ㅌ) 뒤 ㅇ-시작 실질형태소**
경계에 공백을 삽입한다(2026-10-22, dc6d589). 띄어 쓴 입력이 이미 제9항 대표음
테이블(`ᆺ`+공백→`ᆮ`)+link3으로 표준 발음을 내므로, 붙은 입력이 같은 길을 흐른다:
`못알아먹는다`→[모 다라멍는다], `못읽은 사람이 많다`→[모 딜근 사라미 만타](=띈 본과 동일).

과잉 적용 방지 조건 — 이 경계 삽입이 없어야 맞는 클래스:
- 조사·어미·접미사(J*/E*/X*) 앞: 제13항 연음이 정답 (못이[모시], 잘못을[잘모슬])
- 합성어 경계: 제29항 ㄴ 첨가가 필요 (나랏일[나란닐]) — 부사 경계와 무충돌
- ㄹ/ㅁ/ㅂ/ㄱ류 종성: 단어내/밖 결과가 동일해 경계 불필요

mecab-less 모드는 [모사라멍는다]를 유지(Python 원본 패리티). Python 원본은 붙은
못+ㅇ을 여전히 [모사라]로 냄(모시저 실측) — Dart가 원본보다 정확한 두 번째 지점.
**계약 주의**: f1 라벨(Python g2pkk)과 Dart 추론이 붙은 못+ㅇ에서 갈리므로
문장원 표기는 못을 띄어 쓴다.

## 형태소로도 안 풀리는 것 — 예외 사전의 영역

사이시옷 합성어 ㄴ 첨가(나랏+일→[나란닐]) vs 조사 연음(옷+이→[오시])는
**mecab-ko조차 나랏일을 단일 NNG로 분석**해 형태소 경계 정보로도 구분 불가.
원본 파이썬 g2pkk도 `나랏일→나라실`(실측 2026-10-22). 유일한 해법은 idioms
예외 사전 등재(`나랏일===나란닐`) — Dart 포트가 원본보다 정확한 첫 번째 지점.
미등재 잔여: 뱃일[밴닐]→배실, 뒷일[듄닐]→뒤실 (원본·Dart 공통 결함).

## 주입 통합은 교정만 만들지 않는다 — 회귀도 만든다

mecab 통합 직후 전 클래스 배터리가 필수다. 실제 회귀: `2명`이 /B 마커 경로에서
[이명](한자수)으로 — 어노테이션 경로는 boundNounSet만 보고 mecab-less
휴리스틱 경로(pureKoreanCounterSet)와 어긋났다. 수정: /B 분기는 두 집합의
합집합을 본다(2d79196). 동일 원리로 부사 경계 규칙도 대조군(못이·잘못을·못할·
나랏일)을 배터리에 못 박았다.

## 안전장치의 양면

annotate()는 토큰 표면형 합성이 원문(공백 제거)과 불일치하면 원문을 그대로
반환한다. 덕분에 형태소 분석기가 죽어도 파이프라인이 죽지 않지만, 대신
**기능이 조용히 mecab-less로 저하**된다(Case 3: mecab.exe가 etc\mecabrc 부재로
사망해도 g2pkk는 겉보기 정상 동작). mecab 의존 동작을 검증할 땐 /P /B 마커가
실제 발화되는 입력(앉다, 3개)으로 출력을 직접 확인해야 한다.
