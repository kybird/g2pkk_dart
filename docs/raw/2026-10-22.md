### Grounding

### 검색 단서
나랏일, 사이시옷, ㄴ 첨가, 나라실, 나란닐, 합성어 발음, 옷이 오시, 조사 연음, idioms 사전, 나뭇잎 나문닙

### 상황
mecab-less 포트에서 `나랏일`이 일반 연음 규칙(link1 `ᆺᄋ→ᄉ`)을 타서 [나라실]로 출력됨. 사전 등재 단어(나뭇잎===나문닙, 막일===망닐, 삯일===상닐)는 정상이었고 나랏일만 누락.

### 가설
연음 규칙이 사이시옷까지 무차별 적용되는 게 원인이고, 합성어/조사 구분은 표면 문자열로 불가능하므로 규칙 수정이 아니라 예외 사전 등재가 유일한 해법이다. 대조군: 옷+이(조사)→[오시]는 연음이 맞으므로 절대 깨지면 안 된다.

### 판정
가설 확정. `옷이→오시`(조사)와 `나랏+일→[나란닐]`(합성어)은 형태소 경계 정보 없이 구분 불가 — mecab-ko조차 나랏일을 단일 형태소로 분석해 파이썬 원본도 나라실을 내는 한계 실측. 즉 idioms 등재가 정확하고, 이 단어에 한해 Dart 포트가 원본보다 정확해짐. 웃웃 잔여: 뱃일→배실(표준 [밴닐]) 등 같은 클래스 미등재 단어.

### 조치
`_defaultIdioms` 사이시옷 ㄴ첨가 섹션(`나뭇잎===나문닙` 아래)에 `나랏일===나란닐` 추가 + 대조 테스트 신설(나랏일→나란닐 / 옷이→오시). RED(Expected 나란닐 / Actual 나라실) → GREEN, 전체 42→48통과.

## [2026-10-22 discovery] Case 3: 파이썬 g2pkk가 mecab 없이 돌던 진짜 원인은 eunjeon ABI가 아니라 mecab.exe의 etc\mecabrc 부재였다

### Grounding
- Evidence: 전체 트레이스백 `eunjeon\mecab.py:49 swig_import_helper → ImportError("register mecab directory to path")` 안내만으로는 DLL 경로 문제로 읽히지만, 실측: (1) `_MeCab.cp313-win_amd64.pyd` 존재(ABI 정상), (2) `echo ... | C:\mecab\bin\mecab.exe` → `param.cpp(69) no such file or directory: c:\mecab\etc\mecabrc`로 사망, (3) 설치된 g2pkk 0.1.2는 이미 MeCabSubprocess(mecab.exe 래퍼)로 패치돼 있었음. 수정 후 실측: 파이썬 g2pkk `앉다→안따·신다→신따`(mecab 활성), eunjeon 직접 import `pos('앉다')→[('앉','VV'),('다','EC')]`.
- Confidence: 5/5 (수정 전후 실측 대조)

### 검색 단서
eunjeon Python 3.13, DLL load failed _MeCab, mecabrc 위치, param.cpp(69), C:\mecab, swig_import_helper, --user site-packages, lazy installer, mecab.exe subprocess, ground truth

### 상황
이 머신의 파이썬 g2pkk가 mecab-less로 동작(앉다→안다, 3개→삼개)해 ground truth로 못 쓰는 상태. 첫 인상은 "2019년산 eunjeon이 3.13에서 ABI 깨짐".

### 가설
(1차, 기각) eunjeon .pyd가 구 Python ABI라 로드 불가. (2차) 진짜 원인은 따로 두 겹: mecab.exe가 컴파일 기본 sysconfdir인 `c:\mecab\etc\mecabrc`를 찾는데 실제 배치는 `C:\mecab\mecabrc`라 시작부터 죽고, g2pkk의 subprocess 래퍼가 빈 출력을 삼켜 annotate 안전장치가 원문을 통과시킴. eunjeon 임포트 실패는 별개로 lazy installer가 `get_python_lib()`(시스템 site-packages)만 뒤져 --user 설치 pyd를 `eunjeon/data/`로 못 옮긴 것.

### 판정
2차 가설 확정. ABI는 무죄(cp313 빌드가 이미 존재). 에러 문자열이 안내하는 해법(PATH 등록)은 함정 — 실제로는 파일 1개 위치 문제였다. g2pkk의 annotate 안전장치(토큰 합성≠원문 → 원문 반환)가 mecab 사망을 조용한 기능 저하로 바꿔 놓아 진단이 늦어진 구조.

### 조치
(1) `mkdir C:\mecab\etc && copy C:\mecab\mecabrc C:\mecab\etc\mecabrc` — mecab.exe 정상화. (2) `_MeCab.cp313-win_amd64.pyd` → `eunjeon/data/_MeCab.pyd` 복사(의존 libmecab.dll이 data/에 있어 로드 성공). 파이썬 g2pkk·eunjeon 모두 정상화. 나랏일은 파이썬 원본에서도 나라실인 것도 이때 확정(Case 1 근거).

### Related Knowledge
- **Anti-Patterns**: "구형 패키지 + 새 인터프리터 = ABI 문제"부터 의심하기(이번엔 cp313 빌드가 이미 있었고, 원인은 설정 파일 경로) — 전체 트레이스백과 실측(파일 존재·직접 실행)이 먼저다.
- Concepts: [[g2pkk-mecab-less-limits]] (annotate 안전장치의 조용한 실패 양상)
